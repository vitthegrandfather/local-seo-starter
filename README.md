# LocalSEO Starter — AquaFix Pro

Демонстраційний сайт сантехнічного сервісу у Кракові для портфоліо Freelancehunt. Польськомовний контент, три посадкові сторінки послуг, локальна SEO-структура та форма з тестовим надсиланням. **AquaFix Pro — вигадана компанія.** Телефон, e-mail, адреса, години роботи й ціни демонстраційні; проєкт не підтверджує реальних послуг, клієнтів або результатів просування.

У футері кожної сторінки є видимий напис: **“Demo portfolio project — not a real company.”** Немає вигаданих відгуків, Google review widgets або заяв про отримані ліди. Публікацію на Vercel чи Freelancehunt не виконано.

## Що демонструє цей кейс

- Структуру невеликого локального сайту: головна, три послуги, район обслуговування, контакти та інформація про приватність.
- Польські тексти з описом аудиторії, складу робіт, процесу, орієнтовних цін і FAQ.
- Унікальні title та description, canonical, Open Graph / Twitter, sitemap і robots.txt.
- Серверний JSON-LD: Plumber, Service, BreadcrumbList і FAQPage.
- Адаптивний інтерфейс, клавіатурну навігацію, доступні помилки форми та мобільний click-to-call.
- Інтерактивну 3D-сцену з власною геометрією, матеріалами, освітленням і керованим потоком води, узгоджену з кольорами сайту.
- Валідований API форми, чесний demo success state й підготовлені інтеграції через env.
- Відтворювані перевірки production-збірки, основних сценаріїв і Lighthouse mobile.

Готові тексти для портфоліо: [український опис](PORTFOLIO_BLURB_UK.md), [English description](PORTFOLIO_BLURB_EN.md), [три варіанти для ставок](docs/BID_VARIANTS_UK.md).

## Стек і структура

Next.js **16.3.4** з App Router, React **19.2.8**, TypeScript, Tailwind CSS 4. Сім публічних сторінок генеруються статично; `POST /api/contact` виконується на сервері. CMS, авторизації та бази даних немає. Manrope Latin і Latin Extended завантажуються локально через `next/font/local`; браузер не звертається до Google Fonts. Hero використовує Three.js **0.185.1** і WebGL: модуль 3D-сцени динамічно завантажується після наведення, фокусу або натискання, а до цього показується локальний WebP-рендер.

```text
app/                    маршрути, layout, 404, robots і sitemap
  api/contact/          серверна валідація та demo / webhook submit
components/             спільний UI, форма, аналітика, керування 3D-сценою і карта
content/                типізовані польські тексти та дані бізнесу
  geodata/              оригінальні міські полігони та походження даних
lib/                    SEO, валідація, аналітика, 3D-модель, вода й рендерер
public/                 локальні шрифти, SVG, WebP-рендери 3D, OG PNG / SVG, карта
scripts/                генерація карти, рендери 3D, Lighthouse та логічні тести
tests/                  Playwright + axe smoke-перевірки
docs/                   архітектура, джерела карти, тексти для ставок
.env.example            лише порожні / демонстраційні параметри
```

[Архітектура у 10 пунктах](docs/ARCHITECTURE.md). У комплекті передачі скриншоти збережені окремо в сусідній папці `../previews/`; вони не потрібні для запуску застосунку.

## 3D-сцена та ілюстрації

Модель труби, з’єднань і клапана процедурно створена в `lib/plumbing-model.ts`. Сцену доповнюють темно-синя тумба, кам’яна стільниця з опорою, підлога й плитка за умивальником. Рендерер `lib/plumbing-scene.ts` використовує PBR-матеріали, RoomEnvironment з панелями кольорів сторінки, основне, заповнювальне й контрове світло, м’які VSM-тіні та ортографічну камеру. Синьо-сіре покриття, металеві деталі й жовта ручка повторюють палітру інтерфейсу. Положення камери, тумби й корпусу фіксовані; рух курсора їх не обертає.

Нерухома частина сцени разом із VSM-тінями один раз рендериться в HalfFloat render target із текстурою глибини; кеш оновлюється після зміни розміру. Активні кадри компонують цей результат і малюють рухому ручку та воду, не перераховуючи статичні тіні. Кеш також слугує джерелом зображення для водяного шейдера, тому не потрібен повторний прохід усієї сцени для transmission-ефекту. Це рішення зберігає взаємне перекриття об’єктів за глибиною й обмежує роботу GPU; частоту кадрів потрібно вимірювати на конкретному пристрої.

Горизонтальне перетягування ручки в `components/interactive-plumbing.tsx` безперервно задає відкриття від 0 до 100%; ручка проходить відповідну частину чверті оберту. Сама ілюстрація отримує фокус і має `role="slider"`, доступну назву «Otwarcie zaworu» та поточне значення ARIA. Стрілки вправо/вгору додають 5%, вліво/вниз віднімають 5%; Home закриває клапан, End повністю відкриває. Простий клік, тап, Enter і Space не перемикають воду. Окремого видимого повзунка, відсоткового поля чи кнопки немає: під сценою залишається одна підказка «Przeciągnij uchwyt w prawo lub w lewo.». Завершений вибір озвучується прихованим від візуального інтерфейсу live status. Польські тексти зібрані в `content/interactive-art.ts`.

`lib/plumbing-fluid.ts` розділяє подачу з клапана, воду в польоті та воду в чаші; `lib/plumbing-water.ts` відображає цей стан у 3D. Час руху до кожної висоти обчислюється за балістичною моделлю з початковою швидкістю 1,1 м/с і прискоренням 9,81 м/с². Історія подачі зберігає випущену воду: після закривання струмінь обривається біля виходу, а його залишок продовжує падати з прискоренням. Радіус струменя зменшується зі зростанням швидкості за умовою неперервності потоку.

Біла кругла чаша має керамічний матеріал і металевий злив. Висота води нелінійно залежить від об’єму відповідно до внутрішнього профілю чаші. Нормалізований баланс враховує воду, що долетіла, і стік, який залежить від висоти води; після закривання чаша поступово спорожнюється. Передбачені затухання хвиль і одна невелика залишкова крапля з носика. Це обмежена фізично вмотивована модель для інтерфейсу, без повного розрахунку гідродинаміки, калібрування реального обладнання або Blender fluid simulation.

Поверхня струменя, вода в чаші та невеликі бризки з останньою краплею вкладаються у три динамічні водяні об’єкти для малювання завдяки шейдерній деформації й instancing. Водяний матеріал використовує кешоване зображення сцени для видимого ефекту заломлення; це наближення, а не трасування променів крізь воду. Час польоту, неперервність потоку, баланс об’єму, профіль чаші й завершення стоку перевіряє окремий набір `npm run test:water`.

До першої взаємодії показується `public/images/plumbing-3d-closed.webp`. Після наведення, фокусу або натискання завантажується Three.js і створюється WebGL-сцена. Коли ручка, вода й залишковий стік перестали змінюватися, цикл `requestAnimationFrame` зупиняється; активна анімація призупиняється поза екраном і в прихованій вкладці. За `prefers-reduced-motion` сцена показує вибраний стан статично.

Якщо WebGL недоступний або контекст втрачено, перетягування, клавіатурне керування і значення ARIA продовжують працювати. Локальні `plumbing-3d-closed.webp` і `plumbing-3d-open.webp` розміром 900×900 показують закритий стан або відкрите положення для будь-якого значення понад 0%; окремого постера для кожного проміжного кута немає. Це справжні знімки рендера тієї самої авторської геометрії. Вони не генерувалися AI; 3D створено кодом для браузерного рушія, без Blender-проєкту або заяв про виконаний Blender workflow.

Щоб оновити постери після змін моделі, запустіть production-сервер і в іншому терміналі виконайте:

```bash
npx playwright install chromium
npm run art:render
```

Команда запускає `scripts/render-plumbing-posters.mjs` проти локального production-сайту на `http://localhost:3000`. Після отримання нових WebP зупиніть сервер, виконайте `npm run build` і знову `npm run start`, щоб перевірити нові рендери у збірці.

Три ілюстрації послуг — оригінальні SVG, вручну створені за концептами з вбудованого imagegen: труба з клапаном і ключем, змішувач умивальника з викруткою та сифон із ручною спіраллю. Це стилізовані ілюстрації, не фотографії виконаних робіт. Фінальні файли `public/images/plumbing-valve.svg`, `plumbing-installation.svg` і `plumbing-drain.svg` містять векторні елементи без вбудованого растру або текстур; шляхи й alt-тексти зібрані в `content/visuals.ts`. Іконки інтерфейсу походять із Lucide. [Джерела, короткі briefs і ліцензійні повідомлення](docs/ASSET_SOURCES.md).

## Локальний запуск

Потрібні Node.js **22+** та npm. Виконуйте команди з кореня `local-seo-starter`.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Для PowerShell замість `cp` можна виконати:

```powershell
Copy-Item .env.example .env.local
```

Відкрийте [http://localhost:3000](http://localhost:3000). Усі env-параметри необов’язкові: без них сайт працює з локальним URL, без аналітики та з тестовою формою. Не вводьте справжні персональні дані в демонстрацію.

Production-запуск локально:

```bash
npm run build
npm run start
```

## Налаштування через env

| Змінна                     | Значення та поведінка                                                                                                                                                        |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`     | Фінальний origin, наприклад `https://your-project.vercel.app`, без шляху, query або hash. Встановіть перед production build для правильних canonical, sitemap і social URLs. |
| `NEXT_PUBLIC_NOINDEX`      | `false` за замовчуванням. `true` додає `noindex` і робить sitemap порожнім; crawling залишається дозволеним, щоб робот міг прочитати `noindex`. Це не захист доступу.        |
| `NEXT_PUBLIC_GA4_ID`       | Необов’язковий валідний GA4 ID виду `G-XXXXXXXXXX`. Порожнє значення вимикає аналітику й банер згоди.                                                                        |
| `GOOGLE_SITE_VERIFICATION` | Необов’язковий токен метатега Search Console. Створювати GSC property для локального запуску не потрібно.                                                                    |
| `FORM_ENDPOINT`            | Необов’язковий HTTPS URL власного одержувача JSON. Порожнє значення залишає форму в demo mode.                                                                               |
| `FORM_ENDPOINT_TOKEN`      | Необов’язковий bearer token для webhook, лише на сервері.                                                                                                                    |

Порядок вибору базового URL: `NEXT_PUBLIC_SITE_URL` → `VERCEL_PROJECT_PRODUCTION_URL` → `VERCEL_URL` → `http://localhost:3000`. На preview-публікації canonical може вказувати на production origin, якщо Vercel надає його. Для ізольованого preview встановіть потрібні env для відповідного середовища та перебудуйте сайт.

`NEXT_PUBLIC_*` доступні браузеру: це місце для публічних налаштувань, **не секретів**. Локальні `.env*` і токени не комітяться; `.env.example` навмисно включений. Після зміни значень, що використовуються статичними сторінками, потрібна нова збірка.

## Публікація на Vercel

1. Завантажте цей застосунок у власний Git-репозиторій і виберіть **Import Project** у Vercel. Якщо `package.json` лежить у корені репозиторію, Root Directory — корінь; якщо проєкт вкладений, виберіть папку `local-seo-starter`.
2. Залиште preset **Next.js**, команду встановлення `npm ci` та build command `npm run build`. Потрібен Next.js runtime для форми; це не `output: export`.
3. Задайте `NEXT_PUBLIC_SITE_URL` для фінального домену перед production build. Якщо Vercel спершу призначив новий домен, додайте його в env та виконайте redeploy. Решту env можна залишити порожніми.
4. Для preview за потреби встановіть `NEXT_PUBLIC_NOINDEX=true` лише у Preview environment. Для публічного портфоліо залиште видимі demo-позначки й не представляйте адресу як справжній офіс.
5. Після публікації перевірте canonical у HTML, `/sitemap.xml`, `/robots.txt`, 404, мобільну версію і тестове надсилання форми.

Варіант через CLI, з кореня проєкту:

```bash
npx vercel login
npx vercel
# Після налаштування production env у Vercel:
npx vercel --prod
```

Жодних змін коду для стандартного Vercel deployment не потрібно. Ці команди описують наступні дії власника; у межах підготовки кейсу deployment не виконувався. [Офіційна документація Vercel CLI](https://vercel.com/docs/cli/deploy).

## Форма та webhook

Поля: ім’я, телефон, e-mail, район, повідомлення й згода. Спільна валідація працює у браузері та API: довжини обмежені, район має бути одним із 18, checkbox обов’язковий. Honeypot прихований від звичайної навігації. API також перевіряє JSON content type, обмежує тіло 16 KiB і відхиляє сторонній `Origin`, якщо заголовок присутній.

Без `FORM_ENDPOINT` сервер повертає `{ "ok": true, "mode": "demo" }`. У серверний лог потрапляють лише технічні ознаки наявності полів, довжина повідомлення та прапорець згоди. Ім’я, телефон, e-mail, район, IP і текст повідомлення цей demo log не записує. Власної бази заявок немає; можливі стандартні технічні логи хостингу описано окремо на сторінці приватності.

З налаштованим HTTPS endpoint сервер надсилає JSON:

```json
{
  "name": "Osoba Testowa",
  "phone": "+48 000 000 000",
  "email": "test@example.com",
  "district": "Stare Miasto",
  "message": "Test demonstracyjnego formularza. Nie jest to zlecenie.",
  "consent": true,
  "source": "aquafix-pro-demo"
}
```

Honeypot не пересилається. За наявності `FORM_ENDPOINT_TOKEN` додається `Authorization: Bearer …`. Таймаут — 8 секунд, redirects не виконуються; відповідь HTTP 2xx означає прийняття одержувачем і дає стан `delivered`. Це не гарантує подальшої доставки e-mail або створення запису сторонньою системою. Інші відповіді показують помилку без удаваного успіху. Це універсальний JSON webhook, а не готовий контракт Formspree; перевірте формат конкретного одержувача перед увімкненням.

Honeypot і перевірки запитів — базові запобіжники. Немає CAPTCHA, розподіленого rate limiting, перевірки володіння телефоном чи e-mail або промислової системи протидії спаму.

## Підготовка аналітики

Без GA4 ID скрипти Google не завантажуються, банер не показується, а `click_call` і `generate_lead` нічого не відправляють. За наявності валідного ID скрипти й аналітичні cookie дозволяються тільки після явної згоди. Вибір зберігається локально; налаштування доступні через кнопку внизу екрана, відкликання згоди вимикає відправлення, видаляє доступні GA cookie та перезавантажує сторінку.

| Подія           | Коли надсилається після згоди                                |
| --------------- | ------------------------------------------------------------ |
| `page_view`     | Перегляд сторінки, включно з переходами App Router           |
| `click_call`    | Клік на демонстраційний телефонний CTA                       |
| `generate_lead` | Лише успіх налаштованого webhook; **ніколи для demo submit** |

Події не містять контактних даних, району або тексту повідомлення. Query, hash і referrer також не передаються кодом інтеграції. **Вимкніть Enhanced Measurement у GA4 data stream**, якщо потрібен саме цей обмежений набір подій без додаткових автоматичних вимірювань Google. Реальна GA4 property, GSC property, Google Business Profile і рекламні кампанії не створювались. Успішне отримання подій зовнішньою property не перевірялося.
